# e-SUS PEC LXC TLS Implementation

## Scope

Implemented the PEC TLS automation path without modifying VM `101 ESUS-TESTE` or CT `100 NetBird`.

The target architecture is a single edge Nginx in CT `110 nginx` at `192.168.1.139`. The development PEC Java service remains on CT `133 esus-pec-lxc-5437` at `http://192.168.1.209:8080` and is exposed as `https://esus.vinisantana.com`. The production PEC Java service for `https://esus.presidenteepitacio.sp.gov.br` is `http://192.168.1.253:8080`. TLS is terminated by CT `110`; CT `133` must not remain a second Nginx endpoint after CT `110` obtains a trusted certificate for its routes.

## Implementation

The reusable script is:

```powershell
rtk powershell -NoProfile -ExecutionPolicy Bypass -File scripts/esus-pec/Enable-EsusPecLxcTls.ps1 `
  -ProxyCtid <proxy-ctid> `
  -ProxyIp <proxy-ip> `
  -ProxyExpectedHostname <proxy-hostname> `
  -PecIp <pec-app-ip> `
  -Domain <public-domain> `
  -PublicIp <public-ip> `
  -LetsEncryptEmail <acme-contact-email>
```

It reads Proxmox SSH settings from `config/Proxmox.pkrvars.hcl`, executes commands through `pct exec`, and stores TLS material plus Certbot renewal metadata in Infisical after successful issuance. Required values can be passed as parameters or declared in `.env` as `ESUS_PEC_PROXY_LXC_CTID`, `ESUS_PEC_PROXY_LXC_IP`, `ESUS_PEC_PROXY_LXC_NAME`, `ESUS_PEC_LXC_IP`, `ESUS_PEC_PUBLIC_DOMAIN`, `PUBLIC_IP`, `LETSENCRYPT_EMAIL`, and `ESUS_PEC_PRODUCTION_UPSTREAM_URL`; missing values fail the script before changes are applied. For the production domain, use `ESUS_PEC_PRODUCTION_UPSTREAM_URL=http://192.168.1.253:8080`.

Do not use `-DisableApplicationNginx` for the production TLS cutover unless a separate change explicitly retires the CT `133` development route. Production `esus.presidenteepitacio.sp.gov.br` and development `esus.vinisantana.com` have different upstreams.

When issuance is blocked before PEM material exists, record only non-sensitive topology and validation metadata with:

```powershell
rtk powershell -NoProfile -ExecutionPolicy Bypass -File scripts/esus-pec/Set-EsusPecTlsProxyInfisicalMetadata.ps1 `
  -Domain <public-domain> `
  -PublicIp <public-ip> `
  -ProxyCtid <proxy-ctid> `
  -ProxyIp <proxy-ip> `
  -ProxyName <proxy-hostname> `
  -UpstreamIp <pec-app-ip> `
  -LetsEncryptEmail <acme-contact-email> `
  -AcmePublicHttpStatus <http-status> `
  -UpstreamHttpStatus <http-status>
```

The script installs only the TLS termination and ACME tooling when missing:

```text
nginx ca-certificates curl openssl certbot python3-certbot-nginx
```

No PostgreSQL-related packages were installed.

## Validation Evidence

Required validation:

```text
DNS A record matches PUBLIC_IP.
HTTP-01 challenge path is served by nginx on port 80.
The public ACME URL returns HTTP 200 through PUBLIC_IP:80.
certbot.timer or /etc/cron.d/certbot exists.
certbot renew --dry-run succeeds unless explicitly skipped.
https://<public-domain>/ returns HTTP 200 without -k or browser security warnings.
```

Expected certificate properties after migration:

```text
issuer=Let's Encrypt
SAN=DNS:<public-domain>
proxy_nginx=active on CT 110
pec_upstream_http_status=200 from CT 110 to the selected PEC upstream
listen=0.0.0.0:443 on CT 110
```

Infisical presence checks must confirm TLS keys by name and length only; values must not be printed.

## 2026-06-21 Validation Status

Implemented and tested the CT `110` Certbot/Nginx path up to ACME preflight. CT `110` has `nginx`, `certbot`, `python3-certbot-nginx`, `certbot.timer`, Alloy, node exporter, and `prometheus-nginx-exporter` installed. The production PEC vhost for `esus.presidenteepitacio.sp.gov.br` must proxy to `http://192.168.1.253:8080`; `http://192.168.1.209:8080` is only the development PEC upstream for `esus.vinisantana.com`.

The trusted Let's Encrypt issuance is currently blocked by public HTTP reachability:

```text
DNS: esus.presidenteepitacio.sp.gov.br -> 177.190.79.26
production upstream: http://192.168.1.253:8080/ -> HTTP 200 expected from CT 110
development upstream: http://192.168.1.209:8080/ -> HTTP 200
local CT110 HTTPS with bootstrap cert: fails trust as expected
ACME public preflight: ACME_PUBLIC_HTTP_STATUS=000
Let's Encrypt error: Timeout during connect to 177.190.79.26:80
```

Do not issue the production certificate until `PUBLIC_IP:80` forwards to CT `110:80`, CT `110` can reach `http://192.168.1.253:8080/`, and the script is intentionally run for `esus.presidenteepitacio.sp.gov.br`. Do not disable CT `133` Nginx until its development route has a separate validated replacement.

## Rollback

To disable TLS termination while leaving PEC HTTP intact:

```bash
pct exec 110 -- rm -f /etc/nginx/sites-enabled/esus-pec-tls.conf
pct exec 110 -- systemctl reload nginx
```

To remove the TLS files after confirming Infisical has the desired copy:

```bash
pct exec 110 -- rm -rf /etc/esus-pec/tls /etc/nginx/sites-enabled/esus-pec-tls.conf /etc/nginx/sites-available/esus-pec-tls.conf
```

Do not delete or rotate the Infisical TLS secrets until the replacement certificate is deployed and validated.
