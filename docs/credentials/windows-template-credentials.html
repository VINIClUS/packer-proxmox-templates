Windows Template Credentials

Credential Changes in This Update

This update adds example-only variables for the Proxmox API endpoint, Proxmox API token, Windows ISO locations, Windows setup product key, and the temporary WinRM Administrator password. Real secrets must be stored only in config/Proxmox.pkrvars.hcl, which is ignored by git.

Required Credentials and Inputs

Item Variable Where to set it Notes
Proxmox API URL proxmox_url config/Proxmox.pkrvars.hcl Defaults in the example to https://192.168.1.149:8006/api2/json.
Proxmox API token ID proxmox_api_token_id config/Proxmox.pkrvars.hcl Use the Proxmox format user@realm!tokenid, such as packer@pve!packer.
Proxmox API token secret proxmox_api_token_secret config/Proxmox.pkrvars.hcl Grant only the privileges needed to create, configure, and convert the build VM to a template. The token must be able to read node/storage metadata and upload the generated answer ISO. At minimum for storage local, include Datastore.AllocateTemplate; the 2026-05-22 build attempt failed without it. Failed-build cleanup also needs Datastore.Allocate on /storage/local.
VM disk storage permission proxmox_vm_storage_pool Proxmox ACL The API token must have Datastore.AllocateSpace on the VM disk storage path, currently /storage/local-lvm.
VM configuration permission vm_id Proxmox ACL The API token must be able to configure VM options for the build VM path. The 2026-05-22 retry reached VM creation and failed on /vms/9101 with missing VM.Config.Options.
Guest agent IP discovery permission qemu_agent Proxmox ACL The Proxmox builder resolves the WinRM host through the guest-agent API. Grant VM.GuestAgent.Audit and VM.GuestAgent.Unrestricted on /vms/9101 or the build remains in Waiting for WinRM to become available.
Network bridge permission proxmox_network_bridge Proxmox ACL The API token must be allowed to attach the build VM to the configured bridge. After VM.Config.Options and VM.Console were granted, the build failed on /sdn/zones/localnetwork/vmbr0 with missing SDN.Use.
WinRM Administrator password winrm_password config/Proxmox.pkrvars.hcl Temporary password injected into the generated Autounattend.xml answer ISO for Packer WinRM access.
OpenSSH Server access Local Administrator credentials or future SSH keys Windows template runtime configuration The build installs native OpenSSH.Server, enables sshd, opens TCP 22, and sets HKLM:\SOFTWARE\OpenSSH\DefaultShell to PowerShell for automation tools such as Ansible and Terraform. No SSH private keys are stored in the template by this change.
EMS serial console serial0 Proxmox VM hardware and Windows BCD The VM definition adds serial0 as a Proxmox socket and Windows enables EMS/SAC on COM1 at 115200 baud for headless break-glass access when networking or WinRM is unavailable.
Windows ISO windows_iso_file config/Proxmox.pkrvars.hcl Upload the Windows ISO to Proxmox first, then reference it as a datastore path such as local:iso/Win11_24H2_English_x64.iso.
VirtIO driver ISO virtio_iso_file config/Proxmox.pkrvars.hcl Upload the VirtIO ISO to Proxmox first, then reference it as local:iso/virtio-win.iso.
Windows setup product key windows_product_key config/Proxmox.pkrvars.hcl Defaults to the public Windows 11 Enterprise setup key NPPR9-FWDCX-D2C8J-H872K-2YT43 because the uploaded win11_24H2_english_x64.iso exposes Enterprise images. This bypasses setup UI only; it does not activate Windows. Replace it together with windows_edition if building a different edition.

Rotation Guidance

Rotate the Proxmox API token if it is exposed or no longer dedicated to Packer. Change winrm_password whenever a template build is shared outside the trusted automation environment. Never commit the real config/Proxmox.pkrvars.hcl file.

Build-Time Permission Check

Before running a build, execute tests/Test-ProxmoxPreflight.ps1. It verifies local ISO authoring tooling, API reachability, storage visibility, and required ISO presence without printing secrets.

The 2026-05-22 build reached VM creation and failed on /storage/local-lvm because Datastore.AllocateSpace was missing. It also left generated answer ISO files in local:iso because cleanup lacked Datastore.Allocate on /storage/local. After those permissions were granted, Packer uploaded and cleaned the generated ISO, then failed on /vms/9101 with missing VM.Config.Options. After VM.Config.Options and VM.Console were granted, Packer reached the next ACL gate: SDN.Use on /sdn/zones/localnetwork/vmbr0. After SDN.Use was granted, console validation showed Windows Setup progressed to the product-key page, so windows_product_key was added to the generated answer file to keep setup unattended. Console validation then showed the uploaded ISO contains Windows 11 Enterprise, Windows 11 IoT Enterprise, and Windows 11 IoT Enterprise Subscription; the defaults now target Windows 11 Enterprise. A later debug build reached DHCP and WinRM setup, then repeatedly failed to resolve the WinRM host with missing VM.GuestAgent.Audit or VM.GuestAgent.Unrestricted on /vms/9101. After those ACLs were granted, Packer could query the guest-agent endpoint but still waited because QEMU Guest Agent is not installed until after WinRM. The answer ISO now includes Install-QemuGuestAgent.ps1 as a first-logon command so Proxmox can report the guest IP before Packer connects over WinRM. A follow-up diagnostic confirmed the VM config has agent: 1 and Windows starts the QEMU-GA service, but Proxmox still returned 500 QEMU guest agent is not running until the guest has a working VirtIO serial channel. The first-logon installer now adds vioserial\w11\amd64\vioser.inf before installing and starting the QEMU Guest Agent MSI. A later WinRM diagnostic reached the guest IP but returned 401 - invalid content type while AllowUnencrypted was still false on a Public network profile. The first-logon installer now switches Public profiles to Private and reapplies AllowUnencrypted=true after OOBE. It also waits for a network profile, runs Enable-PSRemoting -SkipNetworkProfileCheck, and sets LocalAccountTokenFilterPolicy=1 for local Administrator WinRM automation. The next debug build connected to WinRM and then lost the guest endpoint while uploading the first provisioner script, so the template now uses pause_before_connecting = "2m" to let Windows networking and WinRM settle after the first successful reachability probe. A follow-up build confirmed the pause and advanced into provisioning; the template optimization step now treats protected Windows event logs as non-fatal cleanup skips. The same optimization step preserves active Packer temporary files during cleanup so the provisioner wrapper can finish without deleting its own environment script. The final verification build completed in 22 minutes 39 seconds and created Proxmox template 9101; Packer also removed the generated answer ISO after conversion. The enterprise remote-management update adds serial0 socket hardware, EMS/SAC on COM1, native OpenSSH Server, automatic sshd, PowerShell as the SSH default shell, and the inbound TCP 22 firewall rule.
