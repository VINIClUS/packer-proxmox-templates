Windows Template Credentials

Credential Changes in This Update

This update adds example-only variables for the Proxmox API endpoint, Proxmox API token, Windows ISO locations, and the temporary WinRM Administrator password. Real secrets must be stored only in config/Proxmox.pkrvars.hcl, which is ignored by git.

Required Credentials and Inputs

Item Variable Where to set it Notes
Proxmox API URL proxmox_url config/Proxmox.pkrvars.hcl Defaults in the example to https://192.168.1.149:8006/api2/json.
Proxmox API token ID proxmox_api_token_id config/Proxmox.pkrvars.hcl Use the Proxmox format user@realm!tokenid, such as packer@pve!packer.
Proxmox API token secret proxmox_api_token_secret config/Proxmox.pkrvars.hcl Grant only the privileges needed to create, configure, and convert the build VM to a template. The token must be able to read node/storage metadata and upload the generated answer ISO. At minimum for storage local, include Datastore.AllocateTemplate; the 2026-05-22 build attempt failed without it. Failed-build cleanup also needs Datastore.Allocate on /storage/local.
VM disk storage permission proxmox_vm_storage_pool Proxmox ACL The API token must have Datastore.AllocateSpace on the VM disk storage path, currently /storage/local-lvm.
WinRM Administrator password winrm_password config/Proxmox.pkrvars.hcl Temporary password injected into the generated Autounattend.xml answer ISO for Packer WinRM access.
Windows ISO windows_iso_file config/Proxmox.pkrvars.hcl Upload the Windows ISO to Proxmox first, then reference it as a datastore path such as local:iso/Win11_24H2_English_x64.iso.
VirtIO driver ISO virtio_iso_file config/Proxmox.pkrvars.hcl Upload the VirtIO ISO to Proxmox first, then reference it as local:iso/virtio-win.iso.

Rotation Guidance

Rotate the Proxmox API token if it is exposed or no longer dedicated to Packer. Change winrm_password whenever a template build is shared outside the trusted automation environment. Never commit the real config/Proxmox.pkrvars.hcl file.

Build-Time Permission Check

Before running a build, execute tests/Test-ProxmoxPreflight.ps1. It verifies local ISO authoring tooling, API reachability, storage visibility, and required ISO presence without printing secrets.

The 2026-05-22 build reached VM creation and failed on /storage/local-lvm because Datastore.AllocateSpace was missing. It also left generated answer ISO files in local:iso because cleanup lacked Datastore.Allocate on /storage/local.
