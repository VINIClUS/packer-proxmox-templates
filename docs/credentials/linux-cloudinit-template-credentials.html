Linux Cloud-Init Template Credentials

Credential Changes in This Update

AlmaLinux and Ubuntu cloud-init templates now use the same SSH-based Proxmox CLI workflow as the Debian cloud-init template. The local ignored config/Proxmox.pkrvars.hcl must provide the SSH connection settings. No private key material or API token secret was written to tracked files.

Required Credentials and Inputs

Item Variable Where to set it Notes
Proxmox SSH host proxmox_ssh_host config/Proxmox.pkrvars.hcl Defaults to 192.168.1.149 in the example file.
Proxmox SSH user proxmox_ssh_user config/Proxmox.pkrvars.hcl Must be allowed to run qm create, qm set, qm resize, and qm template.
SSH private key path proxmox_ssh_private_key_file config/Proxmox.pkrvars.hcl Store only the local path. Keep the private key ignored and rotate it if exposed.
AlmaLinux source image cloud_image_url linux/almalinux-10-cloudinit/almalinux-10-cloudinit.pkrvars.hcl.example Uses AlmaLinux 10.1 GenericCloud-latest for x86_64_v2 and verifies CHECKSUM with SHA-256.
Ubuntu source image cloud_image_url linux/ubuntu-26.04-cloudinit/ubuntu-26.04-cloudinit.pkrvars.hcl.example Uses Ubuntu Server 26.04 LTS amd64 cloud image and verifies SHA256SUMS.

Template Runtime Accounts

The default cloud-init users are almalinux for AlmaLinux, ubuntu for Ubuntu, and debian for Debian. SSH keys are injected by Proxmox cloud-init at clone time; no runtime private keys are baked into the templates.
