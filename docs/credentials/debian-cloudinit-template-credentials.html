Debian Cloud-Init Template Credentials

Credential Changes in This Update

This update adds example-only SSH connection variables for local scripts that must run qm on the Proxmox node. Real private keys and local variable files must remain untracked. The 2026-05-23 build used the configured proxmox_ssh_private_key_file value from the local ignored config/Proxmox.pkrvars.hcl; no private key material was written to tracked files.

Required Credentials and Inputs

Item Variable Where to set it Notes
Proxmox SSH host proxmox_ssh_host config/Proxmox.pkrvars.hcl Defaults to 192.168.1.149 in the example.
Proxmox SSH port proxmox_ssh_port config/Proxmox.pkrvars.hcl Defaults to 22.
Proxmox SSH user proxmox_ssh_user config/Proxmox.pkrvars.hcl Use a user allowed to run qm; root is the default operational path.
SSH private key path proxmox_ssh_private_key_file config/Proxmox.pkrvars.hcl Store only the local path in vars. Never commit the private key.
Debian cloud image URL debian_cloud_image_url linux/debian-13-cloudinit/debian-13-cloudinit.pkrvars.hcl.example or local override Defaults to the official Debian 13 trixie/latest genericcloud QCOW2.
Template VMID vm_id Target vars file or script default Defaults to 9200. Use -Force only when replacing that VMID.

Rotation Guidance

Rotate the SSH key if it is exposed or reused outside this automation boundary. Keep API token rotation documented separately in the Windows template credentials document.
